# Maintained analysis producer

This tree has two separate entries: `maintenance.ts::maintainAdmittedProject` for the selected donor-led successor, and `entry.ts` for retained G1 captured analysis. Ordinary source registration now uses the successor under the [startup contract](../../docs/automatic-workflow.md#indexed-lifecycle--ordinary-startup). Matching isolated assets establish that path, not installed activation or clean-machine delivery.

## Maintain an admitted project in one isolated child

`maintenance.ts` calls the retained `CodeGraph.init/indexAll` or `CodeGraph.open/sync` core, preserving donor reconciliation and resolution ordering with the bounded adaptations listed below. Its caller supplies a trusted census and explicit policy-file digests; this API does not discover or admit a project itself. `capture.ts` routes live source access through `../../src/core/analysis-source.ts::createAdmittedAnalysisFileSystem`, including checks before resolver cache shortcuts. Policy drift permanently invalidates that run. Enumeration uses the supplied census, not Git or donor inclusion rules; resolver workers remain disabled, while parser workers receive admitted content.

`storage.ts` reuses `../../src/core/analysis-project.mjs` private-directory/file validation and binds exact external storage with no repository `.codegraph` fallback. The bare SDK entry remains single-owner and requires a prior device/inode receipt to reopen. Concurrent consumers use `../../src/core/native-maintenance.ts::runAdmittedMaintenance`, whose child derives that receipt from a validated completed-run record; no per-repository database configuration is introduced. G1, unmarked and incompatible stores are not adopted.

`../../scripts/pi-nav-build.mjs::analysisBuild` accepts optional `--maintenance-grammars <canonical existing directory>` alongside `--output-dir`. Without that flag its G1 artifact contract is unchanged. With it, `identity.mjs::MAINTENANCE_OUTPUT_ARTIFACTS` supplies the separate maintenance entry, parser/storage workers, CommonJS worker package and `maintenance-schema.sql`; supplied WASM files are copied individually. Both entries share one kernel and retain separate schemas. This is an isolated developer build input, not repository/runtime configuration or asset acquisition. Current proof uses explicitly supplied cached donor grammars and build dependencies, not clean-machine packaging. Publication is per-file, not an atomic artifact-set update; existing-kernel preservation is not yet execution-proved.

`../../src/core/analysis-maintenance-worker.mjs` reuses the existing supervisor and `../../src/core/analysis-parent-pipe.mjs` worker-thread watchdog. It acquires `codegraph-kernel/src/maintenance_writer.rs::acquire_maintenance_writer` before loading the donor bundle. That additive, feature-detected API holds an existing canonical lock file for the actual child's lifetime; it changes neither extraction buffers nor G1 interpretation. Never unlink/replace `writer.lock` to reclaim it. The OS releases it on child exit, including forced termination. A contender returns `busy` without loading the maintainer or changing status. A job receipt alone is not query readiness.

## Apply sectioned corpus policy to the candidate

Add `--respect-policy` to the command above to use `../../src/core/navigation-corpus-policy.ts::enumerateNavigationCorpus`. It compiles an ordered policy snapshot and calls the existing native walker through a private read-only census. Older runtimes, incomplete traversal, oversized census responses, malformed configuration and policy drift are refused rather than treated as permission to index. The existing preparation-root owner rejects unsafe or unbounded roots.

Rules in `~/.pi/agent/navigation-ignore` are machine defaults; `<project>/.pi/navigation/ignore` supplies project rules. `[global]` applies to both lanes, while `[code]` and `[docs]` apply only to their own lane. Ordinary matching preserves file order, including repeated sections: last matching rule wins within each layer. Use `!path` to include; existing `+path` remains compatible. Project rules outrank machine rules. Project includes may override ordinary Git/default exclusions; machine includes cannot undo Git/project exclusions. Curated `.pi-navigation.json` `scope.exclude` prefixes and generated-state, nested-project and symlink safety boundaries cannot be rescued.

```text
[global]
examples/
[docs]
!examples/
```

This excludes `examples/` from the code lane but admits it to the documentation lane. The census decides admission, not language eligibility; documentation indexing itself is not changed here.

The policy-aware candidate rejects excluded explicit files before reading their capture. ## Capture a bounded project without selecting files


## Keep writer and reader connection lifetimes separate

Pi's prepared graph queries use the native Rust SQLite reader only. `../../src/core/pi-nav-native.ts::callAnalysisNavigation` retains filesystem-only private-directory, ownership/link and pre/post device/inode checks; it does not open better-sqlite3 for metadata. In particular, do not add even a short-lived foreground better-sqlite3 preflight against this graph: separate SQLite copies do not share in-process WAL/SHM lock bookkeeping.
