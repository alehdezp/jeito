## Implemented

- Public prepared tools are `explore`, `trace`, and `docs_search`; `code_context` remains internal and unregistered.
- Bundled pi-nav owns `ls`, `grep`, `find`, supported structural fallback, smart source reads, and all live Markdown parsing/owner resolution.
- QMD is the only persisted documentation retrieval index. `src/core/qmd-docs-search.ts` uses the owning project's docs census and admitted filesystem even when `docs.root` is a subfolder; exact refresh paths cannot bypass admission. Supplied admitted bytes go through pi-nav's Markdown parser. Every refresh retires excluded cached sections without reopening their source. Queries pin a read-only SQLite snapshot before checking collection ownership and every active document path, then keep that snapshot through retrieval/inference. An excluded or legacy cache requires refresh rather than query repair. Final policy gates run after awaited provider disposal: revocation cannot escape as a ready maintenance receipt or query reply. This does not cancel work legitimately admitted at query start. Nine focused controls include private-row injection and revocation during embedding/disposal; before-fix controls demonstrated both late-gate failures. The existing byte-correct section projection, SQLite/FTS5/sqlite-vec storage and projection-format generation identity remain.
- `docs_search` returns compact ranked current-section leads. Lexical mode uses exact plus bounded relaxed FTS5 queries. A semantically ready lane combines lexical and compatible vector candidates from owned local QMD models, ZeroEntropy `zembed-1`, Voyage `voyage-code-3`, or OpenRouter `nvidia/nemotron-3-embed-1b:free`, reranks with the selected local reranker, `zerank-2`, `rerank-2`, or `nvidia/llama-nemotron-rerank-vl-1b-v2:free`, restores exact-heading relevance with a bounded title prior, then applies current-authority priors outside explicit plan/history queries and exact titles. Semantic answerability labels candidates as answer-bearing or weak ranked leads; weak scores no longer create a false universal absence.
- `read` owns Markdown outline, exact code-symbol/section/range/mixed selectors, current bytes, and edit authority. `:` and `::` are equivalent selector separators. Code symbols resolve through pi-nav's complete parsed file and must return the current source hash; Markdown selectors are reprojected through pi-nav. Missing, ambiguous, stale, unsupported, or over-budget selectors fail closed. Session-local frontmatter exposure uses a metadata digest, a fair 300-estimated-token per-file allowance with exact title/description precedence, and visible `code`/`related` validation through the same selector contract.
- Config, doctor, prepare, freshen, mutation hooks, cadence, and shutdown waiting use the QMD docs lane. Obsolete project docs configuration migrates through the current lifecycle; obsolete `richDocs` automation normalizes in memory to automatic local-or-ZeroEntropy-or-Voyage inference selection; OpenRouter remains explicit opt-in; obsolete query commands/transports are rejected at query time.
- Session startup separates indexed Core assets from optional Graphify readiness. Eligible unowned roots select QMD independently; retired CRG stores and bindings are neither ownership evidence nor a reason to refuse ownership, so they are never read, adopted, migrated, or deleted. Missing assets never trigger installation or repair.
- Exact Pi Markdown mutations enqueue incremental QMD reconciliation through the existing per-root lane transaction. A lexical lane never upgrades itself into provider work. External changes are found by lifecycle reconciliation, not a watcher.
- Query time never indexes, repairs, installs, downloads models, builds native code, or mutates repository state. QMD FTS5 remains usable after lexical preparation; bounded local, ZeroEntropy, Voyage, or OpenRouter query embedding/reranking runs only for a lifecycle-verified semantic lane and falls back read-only to FTS5 on inference failure. Local QMD inference accepts cached GGUF files only.
- Retrieval readiness is `ready`, `lexical_ready`, or `unavailable`; semantic readiness is independently `ready`, `degraded`, or `unavailable`. Results expose ranking mode, retrieval/native/final scores, title and authority adjustments, BM25/vector/rerank/RRF provenance, per-result answerability status and reasons, weak-lead counts and signals, generation/currentness, latency/privacy, candidate-window lower bounds, path/glob filters, page omissions, and exact `read` selectors.
- Managed corpus search is absent. Semantic inference is either local through the npm-installed `node-llama-cpp` runtime and cached QMD models, or remote through an existing ZeroEntropy key (`zembed-1`/`zerank-2`), Voyage key (`voyage-code-3`/`rerank-2`), or explicit OpenRouter key (`nvidia/nemotron-3-embed-1b:free`/`nvidia/llama-nemotron-rerank-vl-1b-v2:free`).
- Source authority remains centralized in `src/core/source-authority.ts` and `SnapshotStore`; complete current displayed rows are editable regardless of originating tool. The doctrine is `docs/harness-doctrine.md:navigation-harness-doctrine/source-and-mutation-authority#2`.
- **CRG is retired in this change set and is no longer an optional path.** The CRG runtime module, adapter, capability-registry entry, setup routing, and bundled `native/crg` source are being removed; `npm run nav:provision` verifies Core and provisions QMD and never provisions Python. The only optional Python backend is Graphify 0.9.23, installed into one ignored `<installed-extension>/.runtime` by `npm run nav:provision:legacy`, whose `.ready` sentinel is written only after the Graphify import/version and CLI checks pass. Runtime consumers use only extension-relative executables. Retired CRG stores and bindings are never read, adopted, migrated, or deleted. The R5 CRG delivery record is historical: `docs/decisions/r5-crg-clean-break.md:r5-crg-clean-break-stock-plus-one-watchdaemon-patch/decision#2`.
- The owned QMD fork and `node-llama-cpp@3.18.1` install as codeweave-pi package dependencies. Postinstall downloads, validates, loads, and exercises the 318 MiB embedding and 610 MiB reranker models (928 MiB measured cache); repeat installs reuse valid cache entries. There is no global QMD command, and codeweave-pi omits QMD's unused 1.19 GiB query-expansion model.
- Code search reports its active mode: hybrid/vector when semantic enrichment participates and FTS/keyword otherwise. Both modes return prepared graph evidence. Relevance-ranked tests/helpers remain visible because they can locate a subsystem without proving ownership; lexical mode is not a failure or a reason to avoid later calls.
- Natural hashed mutation, stale recovery, certified blocks, file delete/move, syntax diagnostics, and scoped LSP validation remain implemented.
- Public tools return typed invalid-call evidence with accepted forms and claim-aware guidance; malformed batches, duplicate targets, obsolete fields, and incompatible modes execute nothing. Bare-symbol trace ambiguity is distinct: it returns a warning because no structural relation completed, exposes only exact-name retry identities, labels approximate matches as non-retry context, and makes mixed batches partial rather than successful.

Explore defaults to 80 rows per paged native collection and caps at 300; indexed code search/traversal retain structural paging and generation identity, and traversal edges are ordered by proximity to the exact start without dropping native edges. Single-target trace defaults to 50 and caps at 200; batches remain capped at 15 per target. Trace test candidate origins page to the requested limit and prepared source hashes match relative, canonical, and absolute path aliases before current-byte certification.
- Agent operational literacy now has explicit invocation/re-entry/closure semantics: registered prepared tools require no speculative health preflight; cross-domain claims trigger map, unqualified implementation ownership triggers code search, exact identities with open neighborhoods trigger traversal, and one exact structural edge triggers trace. Actual diagnostics bound only the returned claim. The operating reference (`docs/tool-operating-reference.md:jeito-codeweave-pi-tool-operating-reference-and-coverage-audit/how-to-audit-tool-coverage#2`) inventories every public parameter and consequential feature; the operational-literacy doctrine (`docs/harness-doctrine.md:navigation-harness-doctrine/operational-literacy-bridges-reasoning-into-tool-calls#2`) rejects bare-schema handoff, fixed workflows, postmortem-only recitation, and prepared-tool confidence deterrents.
