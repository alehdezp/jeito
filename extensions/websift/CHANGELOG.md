# jeito websift changelog

## Unreleased — 2026-08-25

- [docs] **Tool descriptions identify capability and appropriate use:** `web_answer`, `context7`, and the five explicit Exa/X/Tavily/Linkup specialists now lead with what they do, when that distinct provider method is useful, and the evidence limit that prevents misuse; detailed operating constraints remain in prompt guidelines.
- [fix] **webclaw version guard accepts the reviewed range instead of an exact pin:** URL-bearing spawns require `0.6.16 <= v < 0.7.0` (Homebrew 0.6.23 now passes; the 0.6.16 SSRF floor and the fail-closed ceiling at the 0.x boundary remain), a failed version check re-reads on the next call instead of memoizing the rejection for the session, and version/PATH policy errors carry site-owned recovery advice (align or install the binary, retry unchanged) instead of the generic "change the input" text.
- [fix] **`/web-doctor` reports webclaw version conformance:** an installed binary outside the supported range is a named warning (`webclaw_version_mismatch`) with the alignment command, instead of an unconditional green "found".
## 0.2.3 — 2026-08-12

- [fix] **Valid zeros are successful scoped outcomes across the stack:** Exa/X/Tavily search and Context7/SkillsMP/Pi-package lookup return a provider-valid empty result as success with the executed query/controls, zero count, attempt `ok`, and preserved cost/work/rate metadata. Each zero receipt carries one method-specific mutation; catalog zeros never imply ecosystem absence.
- [fix] **Malformed provider contracts are `unavailable`, never search zeros:** invalid JSON, changed root/row shapes, and all-malformed records classify as provider-contract `unavailable` with retry/alternate-method recovery across Serper, Exa, X, Tavily, Context7, SkillsMP, Pi-package, and Linkup. Genuine fetch/extraction no-content stays `empty`. `web_answer`/`web_search` specialist wrappers pass `operation:"answer"`/`"search"` into recovery.
- [fix] **Exa hard filters are locally adjudicated honestly:** include/exclude domain controls support hostname, `*.subdomain`, and `hostname/path` forms; publication bounds enforce inclusive parseable dates. Only safely observable constraints are enforced — text filters and category are reported as not enforced, unparseable bounds are never silently compared — and zero qualifying rows are a scoped zero with rejected/unverifiable counts and reported cost.
- [fix] **Stale `llm_answer` guidance corrected:** the `$research` skill now states generate-or-reuse intent-keyed synthesis with deterministic cache-file ranges as locator authority, removing the false "new generation is blocked" text.

## 0.2.2 — 2026-08-10

- [breaking] **One-job generic `web_answer`:** reduced the startup tool to `question` plus `q`/`query` aliases, one disclosed Exa attempt, and no fallback. Removed generic `mode`, `claim`, `budget`, `requireFetched`, and provider routing. `$mini-research` now solely owns W1/W2 verification, `$research` owns W3/W4 investigation, and lazy Exa/Linkup specialists retain provider-native controls. Provider prose is visibly provisional and decisive citations must be fetched.
- [fix] **Identity-complete answer output:** every generic and specialist answer reserves all source titles, URLs, evidence statuses, and providers in GCF `sourceIndex` before budgeting prose/structured data and passage records. Oversized passages may be omitted whole with visible counts; source identities cannot disappear silently.
- [fix] **Honest search inputs:** removed fake `limit`; equal `query`/`q`/`term` duplicates normalize visibly while conflicting values fail before dispatch. Raw `country` now reaches the Serper adapter, the sole validator/normalizer and warning owner.
- [fix] **Evidence-safe `web_lookup` recovery:** catalog and name-resolution calls now require `query`/`q`/`term` at the schema and runtime boundaries, while exact Context7 IDs retain a neutral `overview` fallback. Missing requested versions render before ambiguity and never recommend unpinned docs; ambiguous candidates require explicit selection.
- [fix] **Exa incompatibilities fail before spend:** empty `additionalQueries` is schema-invalid; `userLocation` requires a two-letter country code; `company`/`people` category calls reject publication bounds and `excludeDomains` locally. Category is labelled a focus, while documented hard date bounds remain caller-verified after a retained provider violation.
- [fix] **Crawl scope and lifecycle repaired:** `mode:"crawl"` again starts one bounded async subtree job. Bare-glob seeds begin at their literal path prefix; local same-origin include/exclude filtering, dedupe, cap-before-cache, identical-job reuse, and shutdown abort close the reproduced root leakage and orphan-process gaps. A live `https://tokio.rs/tokio/topics/*` call retained five scoped pages with no leakage.
- [fix] **`llm_answer` live and intent-keyed:** async generation deduplicates exact work, honors `wait`, reports completion once, aborts on shutdown, reads exact cache bytes via webclaw `--file`, and rejects writes after concurrent refresh. Immutable `summary-<16 hex>.md` sidecars bind cache path, content hash, objective, and `query_terms`, so distinct questions on one page coexist while exact repeats reuse; legacy `.summary.md` files remain exact-match readable. An adaptive 20-job packet produced 16 verified and 4 partial answers with zero factual drift/failure, followed by a fresh-startup two-intent/reuse proof.
- [fix] **Map scope and bounds are local postconditions:** literal path prefixes, one-segment `*`, recursive `**`, and include/exclude lists now filter same-origin rows locally. Results deduplicate, cap before cache writes, and key cache files by requested scope; multi-seed map remains supported with independent identities.
- [security] **Outbound destination policy:** default-deny loopback/private/link-local/reserved/cloud-metadata addresses before direct requests or webclaw spawns. Direct fetches pin an approved resolved address and revalidate every redirect hop. URL-bearing subprocesses require exactly webclaw 0.6.16 at runtime; reported webclaw/crawl effective URLs re-enter policy before attribution or cache writes. Exact host-owned `network.allowPrivateHosts` permits local development only. Source cards attribute the effective URL and show `Requested` only when different; cache identity remains requested.
- [fix] **Recovery names executable next actions:** rate-limit, timeout, network, empty, policy, and quota guidance no longer promises hidden or caller-enabled fallback. One-provider tools now say retry, refine, fetch another source, or deliberately activate another explicit evidence method.
- [fix] **Conflict-safe aliases:** generic answer, fetch URL, and fetch ranking aliases accept equal duplicates but reject conflicting values before provider or model work.
- [fix] **Isolated configuration snapshots:** `loadConfig` keeps its cached snapshot private and returns defensive clones, preventing one caller's nested mutations from changing later calls.
- [fix] **Balanced lexical search recovery:** `web_search` teaches a 2–6-term first query with at most one constraint, prints the exact query when Serper returns zero organic rows, removes one constraint from narrow queries, and adds one discriminator only to broad queries. Unchanged retries and blind constraint stacking are rejected; fixed-count guidance applies only to Serper search.
- [fix] **Zero matches are search outcomes:** a valid Serper response with no organic rows now records one successful attempt, zero leads, the executed query, and one tool-local mutation without `failureClass`. APPEND retains only evidence routing; `web_search.promptGuidelines` and the research skill own ordinary versus W3/W4 query strategy.

## 0.2.1 — 2026-08-07

- [breaking] **Schema v2 simplification (grill rounds 1–6).** `urls` (string | string[]) is the only required parameter; removed `url`, `responseId`, `crawl_id`, `pattern`, `top`, `question`, `refresh`, `site`. `question` → `objective` (dormant hint: used only by `llm_answer` or the single-URL >5K no-quality-match rescue). Tolerance doctrine: every combination resolves with a transparent note; the only hard error is an empty call; scheme-less hosts are accepted.
- [owned] **Content always shown:** universal 5K full-content cap; `query_terms` is an addition — top-5 (single) / top-3 per source (batch, ordered by relevance) / top-2 per page (crawl) matches with score, exact line range to read, and 3 lines of context; focus markers on full pages; no-match sources show their cache path (read or grep the file).
- [owned] **Crawl:** the URL carries the scope (`https://x/`, `https://x/test`, `/*`, `/**`, `+[a/*,b/*]-[c/*]`); polls are `urls:"crawl:N"` (default 30s soft wait); completed jobs are reported on the next web_fetch call; `query_terms` on the crawl call ranks pages at poll time; listings show title + description + url → path.
- [breaking] **context7** saves the complete body to `.cache/web/docs/<doc>/full.md|json` (agent uses the read tool); the retained-session store (responseId) is deleted.
- [fix] llm_answer resolves the deepseek key from `~/.pi/agent/auth.json` even when XDG_CONFIG_HOME is set.
- [fix] **Map crash (live-host only, reviewer-probed):** `mapManyFlow` fed `ToolResult` objects into the `UrlResult`-shaped progress builder — every map call threw `Cannot read properties of undefined (reading 'length')` whenever the host supplied a progress callback. CI and smokes passed because `onUpdate` was undefined there. Fixed with map-shaped progress details + a top-level `execute` guard (unexpected throws become structured `unavailable` failures with recovery). Regression tests now exercise map with a live `onUpdate`.
- [fix] **Partial-failure contract honored:** webclaw exits non-zero with valid pages/URLs on stdout (documented behavior) — map and crawl now keep the parsed results and report the partial status instead of failing the whole job. Spawn layer guarantees string stdout/stderr; map rows must be absolute URLs.
- [owned] **Output honesty:** `llm_answer` counts a source answered only when the LLM call actually succeeded (failed deepseek calls no longer report "1 answered · 0 failed"); map truncation reports `N of M shown (siteMapCap)`; every result carries `details.operation` (mode that ran, ADR 1.4); the cache line shows the fetch date (freshness is visible on cache hits).
- [breaking] `site`/`refresh` removed from the mode union — scalar values hard-reject with the five valid modes; array-form tolerance (`["site"]`, `["refresh"]`) keeps resolving with notes.
- [fix] **js-needs DB at the sane path:** the adapter passed a cache-rooted root into a module that re-applied `cacheRoot` — records landed at `<root>/.cache/web/.cache/web/js-needs.json` and a nested directory was created. js-needs now uses the cache-root convention like every cache consumer; existing nested pollution is removed.
- [fix] **js-needs rule v2 calibration:** legitimately tiny pages WITH a heading (example.com, 117 chars, 1 heading) were misclassified as JS shells and routed to the paid/failing lane. Both clauses now require a headingless body — all three measured shells are headingless, and tiny static content is shown instead of escalated. Constants remain tunable.
- [security] **LLM lanes treat page content as untrusted data:** `llm_answer` and the >5K rescue prompts now frame the fetched page as untrusted web data (never instructions); answers are labeled as model output over untrusted content.
- [owned] **Error taxonomy consistency:** map spawn failures now classify through the same `mapSpawnFailure` vocabulary as the fetch lane (`network`/`timeout`/`not_found`/`policy`/`unavailable`); `details.operation` appears on flow-level failures too.
- [owned] **LLM output robustness:** `parseSummaryJson` tolerates markdown-fenced and prose-wrapped JSON; `llm_answer` reports when the sections list is truncated at 40 headings.
- [owned] **Cancellation:** fetch spawns honor the caller's AbortSignal (pre-abort check + `execFile` signal) and fail with an `aborted` class instead of continuing invisibly.
- [owned] **Cold-agent guidance:** promptGuidelines now point to `web_search`/`web_answer` for discovery/synthesis, note cache growth at `.cache/web`, and warn that pages echoing their own query parameters can contain secrets in the body. The research playbook's removed-surface claims (`renderJs`, `extract`, Linkup branch) were replaced with the current contract.
- [breaking] **`quota` failure class (3-agent council + coordinator):** provider 4xx responses carrying credit/quota/billing wording (Serper's `400 {"message":"Not enough credits"}` verified live) now classify as `quota` with honest recovery ("top up or switch provider") instead of misleading `invalid_input` ("correct the parameters"). Quota is fallback-eligible, so `web_answer` evidence collection fails over to exa/tavily when Serper is out of credits; the dead lane is skipped for 5 minutes (self-healing; Retry-After honored when present). `web_search` keeps its one-Serper-attempt contract. All 9 adapters now read the error body before classifying.
- [fix] **`web_answer` input-boundary validation:** blank/whitespace questions reject deterministically (`invalid_input: question cannot be blank`) instead of reaching the lanes; `claim` documents verify-only usage; `provider` documents `exa|linkup`; `budget` is `Type.Integer`.
- [fix] **Evidence collection is resilient:** internal search intents use `strategy:"compare"` (healthy-zero searches no longer fatal) and per-query failures are caught and skipped — one dead query no longer aborts verify/research; the final no-source empty throw is preserved.
- [fix] **verify actually verifies at defaults:** default verify budget 3→5 so the "contradicting evidence" query runs (was unreachable at the old default); `answer`+`requireFetched` collects via research-style (question-shaped) queries with an explicit result note, and an omitted budget defaults to 3 with a visible note.
- [fix] **Honest numeric bounds:** pi-packages `limit` schema now states 1–20 (was silently clamped); `budget`/`page`/`limit` reject fractional values.
- [fix] **`fallbackOccurred` is honest everywhere:** unified on `attempts.some(failed)` across web_answer, web_lookup, web_answer specialists, and web_fetch failure paths (was hardcoded false or length-based at 6 sites).
- [fix] **Recovery advice never names nonexistent knobs:** the shared `empty` recovery is operation-aware ("refine the query" / "reformulate the question") instead of suggesting `depth:"deep"`/`strategy:"compare"` that no public tool exposes.
- [owned] **Lookup boundary + descriptions:** `web_lookup` queries reject blanks; context7 resolve-mode documents its `library` requirement; the stale "behind responseId" comment now says `docsPath`.


## 0.2.0 — 2026-08-06

- [breaking] **webclaw+tavily extraction stack (ADR 2.5).** webclaw (local binary, `-f llm` single format) is the universal text extractor; tavily escalates only on JS-needs (DB v2, rule re-learned) or webclaw failure. Removed public params: `extract`, `linkup`, `llm_rich`, `summary_id`, `context`. - [owned] **`mode:"llm_answer"`** answers one question about one URL with the page sections it used (webclaw extract-prompt, deepseek direct via `~/.pi/agent/auth.json`); replaces the llm_rich summary lane. `llm-rich.ts`/`fetch-summary-jobs.ts` retired; `section-rank.ts` survives.
- [owned] **8 proven vertical extractors auto-dispatch by URL shape** (npm, pypi, crates_io, docker_hub, arxiv, huggingface_model/dataset, stackoverflow, hackernews) with typed JSON cached verbatim; `--only-main-content` stays off (13-host verdict); PDFs stay native (webclaw `--pdf-mode` NOT superior).
- [owned] **Onboarding:** `/web-doctor` reports webclaw binary presence with the install command; `/web-setup` and jeito-setup offer installation (brew on macOS, GitHub-release/cargo on Linux).
