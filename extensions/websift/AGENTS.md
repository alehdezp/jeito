# jeito websift contributor invariants

- Read [`docs/adr/AGENTS.md`](docs/adr/AGENTS.md) before adding or changing a consequential decision. It explains what jeito websift is building, the numbered master/child ADR hierarchy, five confidence levels, evidence and implementation metadata, concrete code/document edges, and the user stop gates. `docs/adr/` is the only decision-record authority; `docs/ROADMAP.md` owns execution status.
- Preserve the current ADR-001.003 target: `web_search` is one Serper lexical attempt; `web_answer` is one provisional Exa orientation attempt; five lazy specialists each own one provider/method with no fallback; `$mini-research`/`$research` own verification and investigation; structured provider output uses GCF; fetch/lookup keep their distinct evidence boundaries.
- Fully map and implement the reviewed provider surface, but expose only coherent high-value behavior through the common core or a taught provider specialist. Internal-only provider operations are code, not hidden tools or `tool_search` activation targets. [`docs/ROADMAP.md`](docs/ROADMAP.md) owns the selection reason and sequence.
- Use the installed official SDK contracts for Exa and Tavily and installed source for direct-HTTP providers; do not skip an existing reviewed operation because the current public schema lacks it. [`docs/adr/0005-provider-evaluation-and-guidance/0002-provider-contract-baseline.md`](docs/adr/0005-provider-evaluation-and-guidance/0002-provider-contract-baseline.md) accounts for previous tools versus current capability.
- Search results are leads until fetched. Catalog records remain catalog evidence; never upgrade provider snippets, synthesis, or package/skill records to fetched evidence. `src/types.ts::Source` owns this boundary.
- Keep automatic fallback bounded and visible in `attempts[]`; never add hidden billable retries. `src/routing.ts::runWithFallback` owns retry/fallback policy.
- Use typed common fields when semantics match and separate provider tools when advanced semantics differ. Never add YAML/TOML argument strings, arbitrary provider-option bags, or flattened unrelated provider fields. A discriminated provider branch is acceptable only when it remains teachable and preserves native semantics.
- Preserve only documented aliases and lossless near-valid normalization. Equal aliases normalize visibly; conflicting values fail. Never guess a provider, add a billable attempt, weaken evidence/security, discard a supplied value, or revive the removed multi-provider `web_search.requests[]` surface.
- Treat existing `$research` provider recommendations as apprenticeship hypotheses. Comparative wording in schemas or skills requires an accepted focused scenario result under [`docs/adr/0005-provider-evaluation-and-guidance/0004-benchmark-and-selection.md`](docs/adr/0005-provider-evaluation-and-guidance/0004-benchmark-and-selection.md); no universal provider leaderboard.
- The final package owns `mini-research` for bounded W1/W2 and `research` for consequential W3/W4. Both consume one shared reference corpus under `skills/research/`; never load the current global and extension-owned `research` skill together. [`docs/adr/0005-provider-evaluation-and-guidance/0005-guidance-lifecycle.md`](docs/adr/0005-provider-evaluation-and-guidance/0005-guidance-lifecycle.md) owns migration and evolution.
- Keep exact call construction in descriptions and parameter descriptions; use Pi `promptSnippet` and active-only `promptGuidelines` for dense tool selection, interactions, evidence, grounded cost, and recovery guidance. Keep cross-call operating method in the extension-owned skills and APPEND to concise always-on evidence routing plus W1/W2 versus W3/W4 activation.
- Structured provider JSON stays native in `details` and is encoded losslessly for model-visible `content.text` through the pinned official `@blackwell-systems/gcf` codec. Apply GCF to structured results from every websift tool without projecting away model-relevant native fields; leave fetched Markdown/raw bodies and answer prose as text, use complete-record truncation, and surface encoding failure rather than silently switching to JSON.
- A provider change requires its grounded source and `docs/upstreams/<provider>.md`. Prove a coherent exposed change through one representative Pi tool execution; prove internal-only capability through one representative provider operation. Do not add a test per field, helper, or vendor default.
- Plan the proof budget before coding and follow [`tests/AGENTS.md`](tests/AGENTS.md): reuse the owning test, prove public behavior and real security/billing/data-loss/lifecycle boundaries, and stop when tests drive source architecture or approach implementation growth without a named high-risk justification.
- Live provider checks may consume credits. Run them only when mocked proof cannot establish compatibility and the user has authorized the cost.
- Provider learning proceeds current source and old-schema review → behaviorally distinct focused calls → practical recipes → targeted comparison only for unresolved decisions. Every live packet requires an exact provider/mode/call/cost budget; raw temporal results stay in `.tmp/`, while accepted scoped decisions update their owning ADR/schema/skill surfaces.
- Secrets never enter the model, guided skills, conversation/editor, session entries, logs, notifications, errors, snapshots, or tests; never print a secret value or ask the user to paste one. The single exception is the user-invoked local `/web-setup` command, which may receive a key only inside its masked TUI and write exactly one inline `providers.<id>.apiKey` in mode-`0600` `web.yaml` or one exported assignment in its command-owned mode-`0600` Fish/Zsh/Bash secret file. Bounded shell diagnosis may return recognized variable names and source paths only—never values or evaluated content. This exception never weakens no-secret output anywhere else. `/skill:websift-setup` remains secret-blind guidance and `/web-doctor` remains read-only health ([ADR 4.1](docs/adr/0004-operations-and-evolution/0001-setup-doctor-maintenance.md)).
